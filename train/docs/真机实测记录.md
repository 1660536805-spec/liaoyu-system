## 二、滤波参数寻优（候选对比）

只看肘/腕（idx 3,4,5,6）这四个可靠点：

| 参数 | 平均抖动 | 降幅 | 最大 | 跳变率 | 真实动作 p95 保留 |

| 仅中值 3 | 0.0645 | 27% | 8.531 | 13.37% | 75% |
| 中值3 + EMA0.7 | 0.0596 | 33% | 5.928 | 12.27% | 64% |
| 中值5 + EMA0.6 | 0.0534 | 40% | 3.388 | 10.50% | 55% |
| **中值5 + EMA0.5（现选）** | 0.0519 | **42%** | 2.860 | 9.84% | 52% |
| 中值7 + EMA0.5 | 0.0495 | 44% | 1.926 | 9.17% | 50% |
| 中值5 + EMA0.4 | 0.0499 | 44% | 2.299 | 8.91% | 48% |

**结论 2（为什么选「中值5 + EMA0.5」）**：再往上堆滤波只多降 2 个点抖动，
真实动作却丢一半（p95 保留从 52% 掉到 50% 以下），**判定会明显延迟**。
现场宁可抖一点当场响，也不要滤得太稳而慢半拍。
改这里： `src/engine/cleaner.js`。

## 五、阈值标定（当前值 + 改法）

| 想调什么 | 位置 | 现值 |
|---|---|---|
| 整体灵敏度 | `src/engine/judge.js` 的 `export const THRESHOLD` | **0.55** |
| 抗抖保持帧数 | `MoveJudge` 构造参数 `holdFrames` | **12 帧 ≈0.4s @30fps** |
| 自由模式串扰量 | `export const MARGIN` | **0.10** |
| 某一式松紧 | `MOVES[i]` 里的 `okUp` / `okDown` 区间 | — |

**改法顺序（只调最坏的那一式，别一次性全调）**

1. 某一式**不响** → 先调**这一式**的 `okUp` **下界**（放低），只影响这一式；
2. 实在不行 → 降 `holdFrames`（12 → 10）；
3. 最后才动 `THRESHOLD`（0.55 → 0.50）—— 它**全局生效**，动了八式全变。

⚠️ **两个坑**（`judge.js` 里踩过）：
- 新增判定式**只准用 `okUp` / `okDown`**，不准用 `ok(x, lo, hi)`：`ok` 内部有
  `Math.max(0, …)`，参数传反（lo > hi）会**静默永远返回 0 且不报错**。
- 第 8 式「背后七颠」是**时序动作**（45 帧髋部 y 极差 / 肩宽），
  **单帧调用 `MOVES[7](p)` 永远不亮**。
