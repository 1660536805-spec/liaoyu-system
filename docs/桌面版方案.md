## 2. 为什么是这个方案：手机版是怎么"锁"住的

桌面版最大的坑不是"写个媒体查询"，而是**主壳是一套「设计稿 1:1 复刻 + 整屏重绘」的结构**：

1. **尺子不一样。** `app.css` 里 `html{font-size:min(calc(100vw/47),10px)}`，`@media(min-width:470px){font-size:10px}`。
   也就是 **1rem = 设计稿 10pt**，47rem = 470pt。整套 UI 是按 941×1672 的设计稿等比缩放的。
   桌面只要把 rem 基准改大（10 → 11/12px），所有字号/间距/圆角**同时**变宽松，不用逐个组件调。
2. **锁在竖列里。** `.phone{max-width:47rem}`，整个应用是一根 470pt 的竖列，两端留白。
3. **整屏重绘。** `app.js` 的 `paint()` 直接 `root.innerHTML = PAGES[screen]()`。
   每屏的 `<main>` 里是**扁平的一串子节点**，没有任何可供分列的包装层。
4. **导航是事件委托。** 主壳把 click 委托在 `document` 上、认 `[data-a]` 属性。
   → **往页面里注入按钮，只要写同样的 `data-a` 就能直接导航**，业务代码一行都不用动。
5. **页面用属性标记。** 渲染后 `#app[data-screen="home"]`，这就给了纯 CSS 逐屏定制重排的抓手。

**所以桌面版该做的三件事是**：① 改 rem 基准放大设计系统；② 开壳，把竖列换成「侧栏 + 内容列」；③ 逐屏把扁平子节点分装成两列。
而 ①②③ 全部可以放在**新增文件**里 —— 这就是本方案不动 `app.js/app.css` 的技术前提。

## 5. 新增 / 适配的样式方案

### 5.1 断点体系（6 条断点媒体查询 + 1 条 hover 媒体查询）

| 断点 | 作用 |
|---|---|
| `< 960px` | **不介入**。手机 / 竖屏平板走原有 470pt 竖列 |
| `≥ 960px` | 桌面档：侧栏 224px，内容列 ≤1100px，**rem 10 → 11px**，列间距 `--dt-gap:2.4rem`，内容列内边距 `clamp(20px,2.1vw,34px)` |
| `960–1279px` | 窄桌面补偿档：首页「八段锦/五禽戏/帮我选」三段模式条 `flex-wrap` 折成 2+1（原因见 §7） |
| `≥ 1280px` | 宽屏档：侧栏 248px，内容列 ≤1200px，侧栏项加高 |
| `≥ 1700px` | 大屏档：**rem → 12px**，内容列 ≤1340px，侧栏 264px |
| `≥960px 且 高≤820px` | 1080p「矮窗口」/1366×768：`--dt-gap` 压到 2rem，海报与舞台高度各降一档，保证一屏能看到主要信息 |
| `≥960px 且 高≥1400px` | 竖放大屏：内容列放宽到 1240px，避免中间一条细带 |
| `@media (hover:hover)` | 仅在真有指针设备时开 hover 态与卡片阴影过渡，触屏不受影响 |

### 5.2 开壳：`body` 变网格 + 注入侧栏

```css
body.dt-on { display:grid; grid-template-columns: var(--dt-rail) minmax(0,1fr); }
body.dt-on .nav { display:none; }                 /* 底部导航交给侧栏 */
.dt-side { grid-column:1; position:sticky; top:0; height:100dvh; }   /* 侧栏自己滚 */
#app.phone { grid-column:2; max-width:none; min-height:100dvh; }     /* 内容列整页滚 */
#app.phone > main { max-width:var(--dt-max); margin-inline:auto; padding-top:2.6rem; }
```

侧栏由 `desktop.js` 注入到 `<body>` 第一个位置，结构：品牌 → 主导航（含「开始练」强调块）→ `margin-top:auto` 的底部工具区（通知 / 设置 / 帮助与反馈 / 版本信息）。

### 5.3 逐屏两列：CSS 定格子，JS 装节点

这是本方案唯一"绕"的地方，也是必须绕的地方：

- **为什么不能让 CSS 自己分列？** 因为每屏 `<main>` 里是扁平子节点，没有包装层；用 `nth-child` + `grid-column` 硬凑也能出两列，但**行高会被邻列拉齐**，出现大片空洞。
- **为什么不能直接改 `app.js` 的模板加包装层？** 因为那会让**手机端渲染后的 DOM 变化** —— 项目红线是手机端必须逐字符不变。
- **所以**：由 `desktop.js` 在**渲染之后、浏览器绘制之前**（`MutationObserver` 回调属于微任务）把子节点分装进 `.dt-col--a / .dt-col--b`。

```css
#app[data-screen="home"] > main,
#app[data-screen="audio"] > main, /* …共 8 屏… */ {
  display:grid !important;
  grid-template-columns: minmax(0,1fr) minmax(0,1fr);
  column-gap:var(--dt-gap); row-gap:var(--dt-gap);
}
.dt-col { display:flex; flex-direction:column; gap:var(--dt-gap); min-width:0; }
.dt-col > * { margin-top:0 !important; }        /* 卡片的上边距交给 gap 统一管 */
```

每屏再各自覆写列宽比（例如问答页 `minmax(240px,.78fr) minmax(0,1.22fr)`、音疗页 `1.04fr / .96fr`），并把通栏块 `.top` 用 `grid-column:1/-1` 拉通。

`desktop.js` 里配套了三重兜底：

| 兜底 | 行为 |
|---|---|
| 断点不匹配 | 不注入侧栏、不动 DOM，页面退回手机列布局 |
| **该屏子节点个数 ≠ `LAYOUT` 表里的 `n`** | 该屏**放弃分列**、退回单列，不报错、不错位（`app.js` 以后改结构也不会崩） |
| 全程 `try/catch` | 任何异常都退化为原生单列，**绝不白屏** |

### 5.4 浮层：底部抽屉 → 右侧抽屉

```css
.xs { justify-content:flex-end; align-items:stretch; }
.xs-panel { max-width:560px; height:100dvh; border-radius:2rem 0 0 2rem; transform:translateX(102%); }
```
`openSheet/closeSheet` 的逻辑、`.xs-mask` 的遮罩、内容模板全部复用，只换定位与动画方向。

### 5.5 加载页：把底边横带扶正成右半幅

手机档的 `.load-guqin` 是 `position:absolute; inset:auto 0 0` —— 贴在底边的**满幅横带**，宽度天然等于整页宽，所以手机上不需要任何收边。

桌面把它挪进右列后立刻暴露一个问题：照片自带底色（一块偏暖的墙），和宣纸底不是同一个白，直接摆就是**一个硬边方框**。前后试过 6 版收边，结论是：

| 试法 | 结论 |
|---|---|
| 径向遮罩 `radial-gradient(116% 116% at 50% 46%, …)` | ❌ **半径算错的假修复**：椭圆的 rx/ry = 116%×116% 大于半宽半高，方框四条边全落在「不透明」段（中心到边只占半径的 ~43%），等于没遮。边缘仍是硬切 |
| 径向遮罩改成 `farthest-side` 再算 | ⚠️ 能虚化，但整张图变成一个「椭圆光斑」，反而更假 |
| 图缩进右列、四周径向淡化 | ⚠️ 勉强能用，但右半幅上方留出大片空白，宽视口没被用上 |
| **右半幅通高出血 + 左侧长羽化** | ✅ **采用**。照片只剩左侧一条接缝要处理，`linear-gradient(92deg, 0% → 30% 不透明度)` 一段长羽化就化干净了；上/右/下三边直接出血，不需要收边 |
| 再叠 `mix-blend-mode: multiply` | ❌ **去掉**。实测加与不加**像素完全一致** —— 因为 `.loading-screen{isolation:isolate}` 把叠底背景限制成了透明，叠底根本没生效。留着只会误导后来人以为它在起作用，所以在注释里写明了原因 |

### 5.6 兼容兜底（为旧引擎降级，不影响新引擎）

| 写法 | 原因 |
|---|---|
| `min-height:100vh; min-height:100dvh;` ×5 | `dvh` 需 Safari 15.4+/Chrome 108+/Firefox 101+；旧引擎忽略第二行、用 `vh` 兜底 |
| `inset:auto` → `left/right/top/bottom:auto` | `inset` 简写需 Safari 14.1+ |
| `mask-image` 同时写 `-webkit-mask-image` | 覆盖新旧 Blink / WebKit，Firefox 用无前缀版 |
| `matchMedia.addEventListener` + `addListener` 双写 | 兼容旧 Safari 的 `MediaQueryList` API |
| `overscroll-behavior` | 仅用于侧栏滚动包含，不支持时静默降级 |

## 6. 验收证据

全部脚本在 `outputs/pm-review/`，可复跑。

### 6.1 DOM 级（最强证据）——`probe-additive.cjs`

桌面层是**新增文件**，所以"改前"就是**当前 `app.js/app.css` 本身**。要证明的是：挂上桌面层以后，主壳那棵树一个字符都没变。

| 对照 | 含义 | 结果 |
|---|---|---|
| **A ≡ B** | 470×900，`屏蔽 desktop.*` vs `带桌面层` | **10 屏 `#app` 与 `body` 全部逐字符相同** ✅ |
| **C ≡ D** | 1440×900，`屏蔽` vs `带桌面层后 revert()` | **10 屏 `#app` 与 `body` 全部逐字符相同** ✅ |

> C ≡ D 这一条同时证明了**分列是可逆的、且没有打乱节点顺序**。
> 它当场揪出 `desktop.js` 里两个真 bug，都已修复：
> ① `ungroup()` 只把子节点搬回 `<main>`、**没删掉那两个 `.dt-col` 空壳**，于是"拆列"后 DOM 里永久留着 `<div class="dt-col"></div>`；
> ② 搬回时用 `appendChild` 一股脑塞到末尾，会把未分列的 `.top` / `nav` **挪到列表尾部**，节点顺序错。
> 修法：先摘包装层，再按 `map` 里记录的原始下标排序、整串按序重挂。
> 另外修了 `revert()` 的一处连带问题：`classList.remove('dt-on')` 会留下 `class=""`，`body` 就不再与改前逐字符相同 —— 空则摘掉属性。

```
=== 1440x900 ===  === 1536x864 ===   === 1920x1080 ===  === 2560x900 ===
✅ 全部分辨率 × 全部屏通过
```

同一套断言可在三个内核上跑（`PM_ENGINE=chromium|webkit|firefox`），结果见 §6.5。

### 6.5 浏览器兼容

三个内核 **全部实机跑过**，跑的是同一套断言、同一个探针（`PM_ENGINE` 切换引擎）：

| 引擎 | 版本 | 覆盖 | 结果 |
|---|---|---|---|
| **Blink**（Chrome / Edge / 国产 Chromium 系） | 本机 Google Chrome | 8 档宽 × 10 屏 = **80 组** | ✅ 全绿 |
| **WebKit**（Safari） | Playwright WebKit **26.6**（build 2359） | 5 档宽 × 10 屏 = **50 组** | ✅ 全绿 |
| **Gecko**（Firefox） | Playwright Firefox **155.0**（build 1543） | 5 档宽 × 10 屏 = **50 组** | ✅ 全绿 |

每组断言仍是：横向溢出 = 0、两列成形（`loading`/`practice` 按 0 列判）、侧栏在场（`loading` 隐藏）、底部导航已隐藏、侧栏高亮正确、控制台 0 报错。

引擎侧特性底账（说明为什么不需要写各内核分支）：

- 用到的都是基线特性：Grid / `clamp()` / `position:sticky` / `aspect-ratio` / `gap`(flex) / `:scope` / `mask-image`。
- **没有**用 `:has()` / `:is()` / `:where()` / 容器查询 / `color-mix()` / `subgrid` / `backdrop-filter` —— 全表扫过，一处没有。
- **5 处 `dvh` 全部紧跟一行 `vh` 兜底**（`min-height:100vh` 再 `100dvh`）。最低需求 = `dvh` 支持线：**Safari 15.4+ / Chrome 108+ / Firefox 101+**；更老的浏览器只会忽略第二行、退回 `vh`。
- `mask-image` 同时写了 `-webkit-mask-image` 无前缀版，WebKit / Blink 用前缀、Gecko 用无前缀。
- `desktop.js` 只用了 ES5/ES6 基线 API（`Map` / `MutationObserver` / `classList.toggle(cls, force)` / `Node.isConnected` / `matchMedia.addEventListener`，且带 `addListener` 回退）。

> ⚠️ **跑跨引擎验证时本机有两个环境坑**（都不是产品问题，但曾让 Firefox 结果全红，已在探针里内置规避）：
> 1. **环境代理**：本机导出了 `HTTP_PROXY=http://127.0.0.1:61910`。Chromium 内建 bypass localhost，**Gecko 不会** —— Firefox 会把 `127.0.0.1:5400` 的请求发给代理，且用**绝对形式 URI**（`GET http://127.0.0.1:5400/?screen=home`），本地预览服务的路径解析当场失效、回 404，症状是「`app.js` / `desktop.js` 随机加载失败」。
>    对策：给浏览器进程**剥掉 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY`（大小写各一份）**，并让 Firefox 走直连（`network.proxy.type=0`）。
> 2. **Firefox 内容进程沙箱**：受限沙箱里报 `sandbox initialization failed: Operation not permitted`，表现为 `launch()` 成功但 `newPage()` **永久挂起**（不是超时，是真的不返回）。
>    对策：`security.sandbox.content.level=0` + 关进程隔离（只影响测试环境，不影响渲染结果）。

## 7. 已知边界与取舍（如实列出）

1. **`practice`（跟练页）不做两列。**
   它是舞台型：拆两列后舞台会变窄，姿态识别的画面反而更小。所以只做「舞台居中放大 + 两侧工具贴边 + 控制区居中」。
   （`loading` 也不走通用的 `.dt-col` 分列 —— 因为它的右半幅图需要通高出血，用 CSS Grid 直接摆更干净，见 §5.5。）
2. **960–1279px 这一段，首页模式条折行成 2+1。**
   两列分完后单列只剩约 365–490px；模式条里「经典·全身调养 / 灵动·强筋养气 / 智能推荐练习」是 `white-space:nowrap`，压不下去 —— 1024×768 实测右列溢出 **24px**（会出横向滚动条）。已在 `960–1279` 段让它折行，1280 以上仍是一行。这是**有意取舍**，不是没修。
3. **s4 跟练页的像素比对无分辨率。**
   该页有真实视频/姿态画面，同版本连采也差 1.2%。桌面改动对它只做**取值验证**（`framing.test.mjs` / `probe-s4-vis.cjs`），不做像素判定。
4. **侧栏的 5 个导航项与手机端底部导航同序，但侧栏多一个「身体数据」。**
   桌面没有"从我的页再点进去"的动线习惯，直接给入口更省事；该页手机端仍从「我的」进，两端数据同源。
5. **超宽屏（≥1700px）内容列会被 `--dt-max` 封顶并居中，于是加载页的右半幅图只出血到内容列右缘、不到视口右缘。**
   实测 1920 时两侧各留约 158px 纸边、左右对称。取舍：保持「全站内容都在居中的内容列里」这一致性，而不是为开屏单开一个满视口的例外。若希望开屏真正满视口，把 `#app[data-screen="loading"] > main.loading-screen` 的 `max-width` 放开即可（一行）。
6. **问询页的模型服务仍未接入**（与手机端一致）。
   桌面版只是把它的交互结构铺开；诚实标注（"尚未接入模型服务、回复为本地占位"）原样保留，**没有被桌面版美化掉**。
7. **未做的**：暗色模式、键盘全站 Tab 序列优化、桌面端右键/悬停增强菜单、窗口拖拽分栏。均不在本次范围内。

## 8. 回滚方式

桌面层是**两个独立文件 + `index.html` 里 4 行引用**，回滚成本极低：

- **临时关掉**：删掉 `index.html` 里那 2 行（`desktop.css` 的 `<link>` 与 `desktop.js` 的 `<script>`）即回到纯手机版；或运行时 `window.__xyDesktop.revert()` 一键拆卸（已验证可完整还原）。
- **彻底回滚**：删除 `dist/desktop.css`、`dist/desktop.js`，并撤掉 `index.html` 的 4 行新增。
- `dist/app.css` 与 `dist/app.js` **不在回滚范围内 —— 因为它们本次根本没被改过。**
