## 一、双入口并存

| 入口 | 链接 | 形态 | 业务规则 |
|---|---|---|---|
| 旧（默认） | `#/onboarding` | 文字列表 + 「下一题 / 完成」 | 基准 |
| **新（本次）** | `#/onboarding-v2` | **插画卡 + 7 点步进 + 上一步/下一步/跳过** | **与旧完全一致** |

**默认行为零变化**：不带 `?ia=art` 参数时，代码路径与改造前完全相同。

带 `?ia=art` 打开时，若本机 `localStorage` 没有 `xianyang.onboardDone`，
则从首页/欢迎页/启动页自动落到 `#/onboarding-v2`。分流逻辑在 `App.vue` 的 `onMounted`。

**为什么用 URL 参数而不是换构建**：同一份产物同时提供两套 IA，
对比时不用起两个服务，也不会把线上既有行为污染掉。

## 四、关键实现决策

### 1. 业务规则逐字沿用，零改动

`applyRecommendation()` 与旧 `OnboardingView` 逐字一致——题目顺序、选项顺序、
五音推荐分支（`gong` / `shang` / `yu` / `zhi`）全部相同。
**换 UI 绝不能顺手改推荐结果，否则问卷就失去意义了。**

新增落盘键：

| key | 用途 |
|---|---|
| `xianyang.onboardDone` | 走完七步 = `'1'`，`App.vue` 用它决定是否再弹问卷 |
| `xianyang.kneeFlag` | 第 7 题答「是」时写 `'1'`。旧版读了 `knee` 但没参与运算，这里先落盘备后续接阈值 |

### 2. 旧版读答案用的是**下标**（这里也是）

`answers[i]` 存的是选项下标而非文本（插画卡和文字行都是如此），
所以旧版 `applyRecommendation()` 里 `a[0]` 直接当字符串比较是个已存在的隐患。
本组件改为 `questions[i].options[answers[i]]` **按题目取对应选项文本**，
语义更稳；推荐结果与旧版一致。

### 3. 未选提示**不弹 toast**

队友原版点「下一步」未选时 `toast('请选择一项后再继续')`，
弹层会盖住插画卡。这里改成**按钮上方的就地提示**（`.warn`），
保持页面可读、不遮挡。按钮同时是 `disabled` 态。

### 4. 字体分工

题干预设文字用 `--font-serif`（书法体栈），说明文字与选项用 `--font-ui`（无衬线）。
书法体 13px 以下笔画粘连，所以只有 ≥20px 的标题用书法体。

### 5. 响应式

- `≤400px`：插画卡改**两列**（470px 下三列每张仅约 130px，插画细节看不清）
- `≤620px 且横屏`：压缩上边距，保证操作条不被顶出视口
