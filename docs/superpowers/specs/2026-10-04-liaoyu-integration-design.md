# 弦养 0.1 集成设计

## 目标与依据

在 `liaoyu0-1` 上交付一个可构建、可运行的 H5 应用：沿用 `main` 的九屏视觉与交互入口，接入 `xianyang-s4` 已实现的摄像头姿态识别、八式判定、古琴音效、设置和练习记录。用户应能从首次进入走到完成练习，再在“我的”中看到本次结果。保留离线资源与本地存储的现有产品范围。

`main` 目前仅有 `dist/` 发布文件，其中 `app.js`、`app.css` 和 `art/` 是界面参考，没有独立的 UI 源码工程。`xianyang-s4` 是 Vite/Vue 3 源码工程，已有检测与音频模块。集成不能只合并 Git 树或在两套页面间跳转；必须形成一套页面状态和数据契约。

## 实施结构

- 在仓库新增 `app/` 作为可维护的 Vite/Vue 工程，移入 `xianyang-s4` 的 `src/`、`public/`、依赖锁文件与必要脚本。根目录 `dist/` 作为构建发布物，构建输出由 `app/` 统一生成。现有根目录预览脚本继续服务 `dist/`。
- 将 `main/dist/app.js` 的九屏流程和 `app.css` 的视觉作为设计基准，逐屏实现为 Vue 组件；复用 `main/dist/art/` 的图片。发布用脚本本身不参与运行时。
- 训练页面直接使用 Vue 工程里的 `poseEngine`、`judge`、`guqin` 和现有跟练控制逻辑。把训练逻辑与页面呈现拆开，让主界面和训练界面共享一个会话控制器，避免在 UI 层复制判定逻辑。
- 对于 `main` 里展示但 `xianyang-s4` 尚无真实能力的入口，只显示有明确行为的页面或说明，不伪造姿态检测、记录或音乐结果。

## 页面与会话数据流

1. 首次进入：加载页 → 问卷 → 首页。用户偏好和身体资料写入独立的本地存储键；读取时验证结构、容错旧数据。
2. 首页：进入音疗、八段锦介绍和个人中心。开始练习时创建新会话，明确所选练习模式，再请求摄像头权限和加载本地模型。
3. 跟练：会话控制器输出 `loading`、`ready`、`camera-error`、`pose-lost`、`move-hit`、`paused`、`completed` 等状态；UI 只订阅状态。每次动作命中须去重，第一至第七式播放对应琴弦，第八式完成后播放合弦并进入总结。
4. 退出、刷新和组件卸载时释放摄像头轨道、MediaPipe 实例、音频与计时器。摄像头拒绝、模型失败或长时间无人入镜时展示现有可用的重试、换设备和手动完成路径，且清楚标明手动结果。
5. 完成或明确退出时，以现有 `xianyang.records.v1` 格式保存一次记录。总结页和“我的”页读取同一记录源；部分完成与完整完成分开显示，刷新后记录仍在。
6. 音疗页使用仓库中真实可播放的音频资源，停止/切页时清理播放器。浏览器不支持自动播放时等待用户手势并给出提示。

## 接口边界

- `session.start(config)` / `pause()` / `resume()` / `stop()` / `dispose()` 是页面调用的唯一训练入口。事件至少包含阶段、当前式号、命中来源、已完成动作和错误原因。
- `records.save(sessionResult)` 与 `records.list()` 负责持久化。事件和记录使用稳定的动作 ID，不靠中文标题匹配。
- 摄像头与模型只在训练/调试页启动；首页、问卷、音疗页不请求权限。
- 本地资产路径从 Vite `base` 派生，保证 `npm run build` 后模型、WASM、琴弦采样与图片均返回成功。手机摄像头仍需要 HTTPS 安全上下文。

## 验证与交付

- 单元/回归：沿用八式判定器、音频、兜底和记录测试，增加会话事件去重、退出清理与记录一致性测试。
- 构建/静态检查：`npm run build` 成功，产物包含模型、WASM、音频和艺术素材；根目录预览脚本能打开新应用。
- 浏览器端到端：用虚拟摄像头或可控姿态输入走首次进入、授权失败恢复、八式完成、音效、总结和刷新后的记录；人工真机复核取景、动作命中与音量。自动化通过不等于真实人体动作准确率已验证。
- 在 README 写清桌面和手机的启动方式、HTTPS 要求、离线资源、记录存储和已知限制。

## 范围与风险

本阶段不添加账号、后端、云同步或其他拳种。主要风险是 `main` 缺少原始 UI 工程，九屏需要从发布脚本与视觉资产重建；另一个风险是浏览器自动化无法替代真人动作标定。实施时优先打通真实主路径，逐屏核对视觉，再做真机验收。
