先说清两边各是什么，比对才有落点。

A ｜本轮之前执行的动作模拟 —— room-baduanjin/room.js 里的八段锦 10 式动作库 + 小人绘制 + 陪练教练状态机（即你现在打开的那份 xianyang-room.html）。

B ｜你提供的那份内容 —— 改动前的原始形态（已备份为 original-backup.html）。它自己的注释写得很直白：
// 首页太极小人：起势 → 云手向右三步 → 云手向左三步回到中间 → 收势，循环 33.5 秒。
const TJ={UA:50,FA:48,LOOP:33.5,STEP:58,CYCLE:4} … —— 也就是一招云手、四个姿势常量、33.5 秒无限循环。

一句话结论：「用户不清楚下一个动作怎么做」的根因，是 B 根本没有「下一个动作」—— 它的时间轴是 t = (t + dt) % 33.5，永远在「起势 → 云手左 → 云手右 → 收势」里打转， 既没有「式」的概念，也没有「你做完没有」的概念。「一直停留在一个动作上循环等待」不是 bug，而是它的设计。

二、相同点（同源部分）

两边是同一间房、同一个小人、同一套 IK 骨架的两个阶段。以下部分是 A 直接继承 B 的：

场景与造型（逐字相同）

  • 灰蓝立体房间、墙角透视、地面镜面倒影
  • 小人造型 TJ_DEFS / TJ_ARM / TJ_BODY：白色练功服、腰带、发髻、飘带、皮肤渐变
  • 腰带飘带 tjChain：同一套简易 Verlet 链
  • 倒影机制：房间本体与地面各一个 SVG 实例，共用同一个 pose，保证严丝合缝
  • 墙上五音诗句 ROOM_POEM（未删，仍在场）

IK 骨架与调用链（同构）

  • 两段式：上臂 UA=50、前臂 FA=48
  • 都把腕距夹到 d ∈ [|UA−FA|+.5, UA+FA−.5]，避免三角形无解
  • 都用 acos((UA²+d²−FA²)/(2·UA·d)) 解肘角
  • 调用链一致：const {e:Eb,h}=tjIK(肩, 目标腕, side)，A 只是多传了一个取支记忆 mem
  • 时间骨架一致：requestAnimationFrame + 单帧 dt 钳制（B 用 0.05 秒、A 用 50 毫秒，等价）

还有一层「意图上」的相同：都让手绕肩划弧。B 的云手用 [px−10+60cosθ, 258−30sinθ] 让手绕圈；A 把这一招抽象成极坐标 (r,θ)，成为整个动作库的统一存储格式。

四、可能的偏差（需要你知道的风险）

这几条是比对里对不齐或者性质不同的地方，不是失败，但值得你心里有数：

#偏差说明
1人形比例不是严格等比 换算用 VS=1.367、VMX=200−120·VS、VGY=434，但两套人形的腿 / 躯干 / 臂 / 肩宽比例并不相同（1.367 / 1.517 / 1.633 / 1.2）。所以 A 的姿态是「换算近似」，视觉一致但几何上非同构。若有「必须与原版严格同形」的要求，这里存在残差。
2速率峰值性质不同 120Hz 逐帧扫描：A 全周期最大单帧位移 1.887px @「调理脾胃须单举」u=0.277（wrL）；按 1/1.367 归一到 B 的尺度 ≈ 1.38px/帧，略优于 B 当时的 1.47px 残留。但要注意：A 的峰值不是孤立尖峰（单举有 181 帧连续超 1.2px 阈值 = 持续快挥），而 B 当时的 1.47px 是孤立跳变。两者性质不同，不能只看数字大小。
3「提示」的语义变了 B 的提示是氛围（五音诗），A 的提示是任务指令（第 N 式 / 要领 / 倒计时）。A 把诗留在了墙上，但教练条是新增的第二层信息；若你要保持「安静的氛围感」，教练条的视觉权重可以再调。
4URL 参数解析曾有一处 bug（已修） 旧解析把 location.search + location.hash 直接拼接，于是 ?mode=free#debug 会把 mode 读成 "free#debug" 而回落 full。已改为把 ? 与 # 统一当分隔符 —— 这也正是它此前无法被端到端测试切到自由档的原因。
5等待上界是默认值 跟练 2.6–8.0s、宽限 4.0s（随每式时长缩放）。觉得等太久或太短，只需调 CP 里的常量，无需动结构。

五、陪练教练：机制说明

5.1 触发方式

入口怎么到你会看到
完整引导（默认）直接打开页面，或 URL 不带参数教练条：第 N 式 / 共 10 式 + 式名 + 阶段 chip + 要领 + 进度条 + 「开始跟练」
开始跟练点 开始跟练进入 demo：教练从第 1 式（起势）开始逐式示范
自由浏览点 切到自由浏览，或 URL 加 ?mode=free原来的自由控制台：上一个 / 下一个 / 播放 / 连播 —— 不与状态机冲突，适合单独复习某一式
两档互切教练条 / 自由条里的互切按钮整页重载切换，规避 hash 路由改 query 不重建组件的坑

5.2 动作切换与等待机制（一式的生命周期）

idle 准备开始→ demo 教练示范→ follow 轮到你了→ grace 等你确认→ 下一式 demo …
阶段教练在做什么用户能做什么怎么离开
demo 示范中按「动作时长 × demoK」完整播放该式 只能「跳过本式」——示范期点「我练好了」不算数（抢做也不放行）示范放完 → follow
follow 轮到你了停在该式起收位等你 「我练好了」/「再看一遍示范」/「跳过本式」 hit() → stepDone；或到 上界（2.6–8.0s）→ grace
grace 等你确认文案明说「不点的话 N 秒后也会自动继续」 「我练好了」/「再练一会」/「跳过本式」 hit() → stepDone；或 4.0s 到点 → 直接下一式
stepDone 本式完成0.8s 完成提示，进度条走满—0.8s 后 → 下一式 demo
关键设计：每一个「等」都有硬上界。这正是「避免一直停在同一个动作上循环等待」的落地方式 —— 教练一定会等你，但不会无限等：跟练到点进宽限、宽限到点自动放行。 实测量化结果：全程一次都不点，十式也能在 160.0s 内走完，且实测耗时与理论上界逐毫秒相等（说明既无缺口、也无停死）。

5.3 动作序列推进规则

入口在哪些阶段可用效果额度
hit() 「我练好了」follow（t≥900ms 防误触）/ grace→ stepDone（0.8s）→ 下一式不限
timeout 兜底follow / grace 到点直接 → 下一式（reason = timeout）自动
「跳过本式」demo / follow / grace立刻 → 下一式不限
「再看一遍示范」follow / grace→ 回到 demo 重放本式每式 1 次
「再练一会」grace→ 回到 follow 续练每式 1 次
「重头再来」任意→ 第 1 式 demo不限
第 10 式后再推进—→ allDone「全部完成」并停住—

两条保护：① 每式开头重置重放 / 续练额度，防止在某式上无限纠缠； ② 单帧 dt 截断 50ms，切回标签页不会把好几秒当成一帧补上（否则会「瞬移」跳过整个等待）。 ③ 式号单调不回退（restart 除外）。

教练条的六个阶段：① 准备开始（灰） ② 示范中（青瓷绿，只留「跳过本式」） ③ 轮到你了（赭石，出现「我练好了」，并给出「约 N 秒后进入确认」） ④ 等你确认（深赭红，出现「再练一会」，明说「不点也会自动继续」） ⑤ 本式完成（进度条走满） ⑥ 全部完成（「重头再来」）。

六、结论

A 与 B 是同一间房、同一个小人、同一套 IK 骨架的两个阶段。 B 是「一招云手、33.5 秒氛围循环」；A 把动作层换成「十式有序库 + 极坐标腕位 + 连续取支 IK」， 并在其上新增了陪练教练层（示范 → 跟练 → 有界等待 → 推进）。

对应关系可以概括为三句话：场景造型原样保留、动作层整层替换、教练层从零新增。 偏差集中在两点：人形比例换算非严格等比（视觉一致、几何近似）， 以及速率峰值的性质不同（A 是持续快挥、B 是孤立跳变）。

你提出的四条要求 —— ① 逐项比对（本报告第一至四节）② 教练先示范、后跟练（demo → follow） ③ 每步等待且不循环卡死（follow/grace 双段 + 硬上界）④ mode=full 逐动作连贯引导 （29/29 + 27/27 验证）—— 均已落地。
