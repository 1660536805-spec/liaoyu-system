## 2. 产品概述

### 2.1 一句话产品

> **做一个对的动作，拨响一根古琴弦；练完一套八段锦，等于弹完一曲古琴。**

弦养是一款手机网页 H5：用户面对摄像头练习八段锦，系统使用姿态识别判断动作是否达到要求；每个动作命中后触发对应古琴弦音，完成第八式时触发七弦齐鸣，并保存本地练习记录。

### 2.2 产品价值

1. 把“跟练”转化为即时、可听见的反馈；
2. 用“动作—弦音—完成一曲”的隐喻增强坚持动力；
3. 不依赖登录、后端和联网，适合现场路演与弱网/断网环境；
4. 通过五音氛围、阶段音乐与身体数据，逐步从普通跟练扩展到定制体验。

### 2.3 用户与使用场景

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 路演观众 | 现场首次体验 | 3 秒看懂、快速授权、做一个动作就能听到琴响 |
| 普通用户 | 手机日常练习 | 不登录、不安装、打开即可练，能看到练习记录 |
| 定制用户 | 长期练习 | 补充身体数据后获得更贴合的推荐、反馈和食谱内容 |
| 团队测试者 | 开发与真机验收 | 能按路径完整复现问题并留下截图和设备信息 |

### 2.4 非医疗产品边界

弦养是运动与音乐体验产品，不提供诊断、治疗或医疗建议。

- 禁止使用：治疗、祛湿、根治、调理好、改善某疾病等医疗化表述；
- 推荐使用：舒缓、放松、适合久坐、有助于入睡、提振精神、照顾某个状态等；
- 五行五脏内容用于文化意象、氛围和编排叙事，不作为医疗判断；
- 用户界面不直接展示“你肝不好”“入脏”“主音”等诊断式表达。

## 3. 范围与版本策略

### 3.1 P0：必须交付

P0 是产品能否交付的底线：

1. 打开首页并理解产品用途；
2. 进入跟练页并完成摄像头授权；
3. 展示实时摄像头画面与人体骨架；
4. 支持八段锦一套 8 式的动作判定；
5. 前 7 式命中时触发一至七弦之一；
6. 第 8 式完成时触发七弦齐鸣；
7. 练习完成后显示总结并保存本地打卡记录；
8. 断网后仍可运行核心流程；
9. 摄像头或识别失败时具备预录视频兜底；
10. 手机端能够打开并完成真机验收。

### 3.2 P1：本次冻结但可降级

- 启动页、欢迎页和快速问卷；
- 跟练准备页的模式与阶段选择；
- 音疗页、自由播放与呼吸引导；
- 身体数据问卷与定制版增强内容；
- 练习阶段展示；
- 总结页详细反馈与单条食谱卡片；
- 基础设置、历史数据和样式入口。

### 3.3 P2：明确不作为本次交付底线

- 实时逐句动作纠错；
- 五禽戏、太极拳等第二套可识别拳种；
- 账号、云同步、后台管理；
- 真人 3D 建模；
- 复杂动效与复杂社交功能；
- 44 首赏听曲目全部配齐音源。

### 3.4 冲突裁决顺序

出现时间、技术或体验冲突时：

> **保 P0 拨弦出声 > 保关键路径 > 保现场讲解完整 > 保合规 > 再做视觉加分项。**

## 4. 产品流程与信息架构

### 4.1 首次进入流程

```text
启动/加载页
  ↓
欢迎页（仅首次）
  ↓
快速问卷页（可跳过）
  ↓
首页 / 今日
  ↓
跟练准备页
  ↓
实时跟练页
  ↓
练习总结页
  ↓
首页与本地记录
```

### 4.2 主导航

底部 Tab 固定为：

1. **音疗**：自由听音、呼吸/放松字幕；
2. **开始练**：默认主入口，承载首页/今日；
3. **我的**：身体数据、阶段、历史数据和设置。

### 4.3 普通版与定制版

| 项目 | 普通版 | 定制版 |
|---|---|---|
| 进入方式 | 默认进入 | 在“我的”补充身体数据后自动生效 |
| 核心跟练 | 相同 | 相同 |
| 首页推荐 | 基础推荐 | 根据长期身体数据增强 |
| 总结反馈 | 通用反馈 | 身体数据相关的更细反馈 |
| 食谱 | 锁定蒙层 | 展示单条推荐与收藏入口 |
| 退出方式 | 不适用 | 删除身体数据后恢复普通逻辑 |

定制版不是独立子系统，不设置切换、退出或关闭按钮。

## 5. 页面与交互规格

## 5.1 启动页 / 加载页

### 目标

初始化本地模型、准备音频，并让用户理解即将使用摄像头。

### 页面元素

| 元素 | 规格 |
|---|---|
| 品牌名 | 弦养 |
| 副标题 | 以身为琴，以动为弦 |
| 加载文案 | 正在准备古琴音色与动作识别… |
| 主按钮 | 进入弦养 |
| 失败态 | 重试 + 悬浮示例入口 |

### 关键行为

- 首次加载完成后进入欢迎页；
- 非首次进入直接进入首页；
- 音频初始化必须由用户点击行为触发，点击“进入弦养”时调用音频上下文恢复；
- 模型加载失败时不能白屏，必须提供重试与预录示例入口。

## 5.2 欢迎页

仅首次展示。内容包括品牌、副标题、核心卖点“八段锦 × 古琴音疗 · 做对动作，拨响一弦”、定制版提示，以及“开始体验”和“跳过”入口。

## 5.3 快速问卷页

### 目标

7 题、约 1 分钟完成，产出今日拳种、五音氛围和练习时长推荐；允许跳过。

### 题目

| 序号 | 题目 | 选项 |
|---|---|---|
| 1 | 最近哪里容易不舒服？ | 颈肩 / 腰背 / 脾胃 / 睡眠 / 情绪 / 没有 |
| 2 | 每天久坐时长？ | 小于 4h / 4–8h / 大于 8h |
| 3 | 运动基础？ | 零基础 / 偶尔练 / 有规律 |
| 4 | 今天想练什么氛围？ | 平和 / 提振 / 放松 / 帮我选 |
| 5 | 每天可投入多久？ | 5 分钟 / 10 分钟 / 15 分钟以上 |
| 6 | 更想练什么？ | 八段锦 / 五禽戏 / 帮我选 |
| 7 | 是否有膝盖不适？ | 是 / 否 |

### 默认逻辑

跳过问卷时默认：八段锦 + 宫调 + 全套 8 式。Demo 阶段五禽戏仅展示胶囊文案，实际仍进入八段锦练习。

## 5.4 首页 / 今日

### 核心原则

首屏唯一视觉重点是“开始练”大按钮；不让其他入口抢夺注意力。

### 页面内容

- Logo：弦养；
- 日期/节气：如“今日 · 霜降”，应支持动态替换；
- 今日功法卡片；
- 开始练按钮；
- 胶囊切换：八段锦 / 五禽戏 / 帮我选；
- 底部 Tab：音疗 / 开始练 / 我的；
- 已完成状态：今日已练，再练一次；
- 定制状态：显示增强推荐文案。

### 交互

- 点击开始练 → 跟练准备页；
- 点击拳种胶囊 → 即时更新主卡片，不重复问卷；
- 点击音疗或我的 → 进入对应 Tab。

## 5.5 跟练准备页

### 页面内容

- 模式：全套 8 式，约 12 分钟；招牌 3 式，约 5 分钟；
- 阶段：阶段一·点、阶段二·线、阶段三·面；
- 取景提示：后退 1.5–2 米、全身入镜、正面受光；
- 主按钮：启动摄像头并起式；
- 悬浮入口：查看预录演示。

### 摄像头权限

- 未请求：主按钮触发浏览器权限；
- 允许：进入实时跟练；
- 拒绝：显示设置指引与预录示例；
- 手机端必须使用 HTTPS 或 localhost，普通局域网 HTTP 不能作为稳定摄像头授权方案。

## 5.6 实时跟练页

### 页面结构

| 区域 | 内容 |
|---|---|
| 顶部 | 当前式名、当前弦/音信息、设置入口 |
| 中部 | 摄像头画面、33 点人体骨架 |
| 左下 | 头/身体朝向等辅助信息 |
| 右下 | 头部朝向圆形/椭圆提示 |
| 底部 | 七弦进度、动作提示、退出入口 |

### 八式映射

| 式序 | 招式 | 弦层反馈 |
|---|---|---|
| 1 | 双手托天理三焦 | 一弦 |
| 2 | 左右开弓似射雕 | 二弦 |
| 3 | 调理脾胃须单举 | 三弦 |
| 4 | 五劳七伤往后瞧 | 四弦 |
| 5 | 摇头摆尾去心火 | 五弦 |
| 6 | 两手攀足固肾腰 | 六弦 |
| 7 | 攒拳怒目增气力 | 七弦 |
| 8 | 背后七颠百病消 | 七弦齐鸣 |

### 识别状态

1. 等待动作：显示当前式和动作提示；
2. 识别中：绘制骨架，提示“保持，听到弦音即成功”；
3. 命中：弦位亮起、播放声音、进入下一式；
4. 识别失败：提示调整姿势和取景；
5. 完成：七弦齐鸣，进入总结页。

### 七弦进度视觉

- 未命中：辅助灰；
- 当前：朱砂红闪烁；
- 已命中：碧玉绿；
- 第 8 式：七个点同时亮起。

### 核心判定要求

- 33 点姿态关键点使用本地 MediaPipe Pose Lite；
- 连续保持约 300–500 ms 后才算命中，避免抖动误触发；
- 每式只触发一次，使用锁存机制；
- 第 8 式为时序动作，不能用单帧判断；
- 新增判定逻辑优先使用既有 `okUp` / `okDown` 约定，避免参数方向错误；
- 摄像头断开或长时间无有效识别时，在 3 秒内切换预录视频兜底。

## 5.7 练习总结页

### 普通版与定制版差异

| 模块 | 普通版 | 定制版 |
|---|---|---|
| 分数与评价 | 展示 | 展示 |
| 琴谱可视化 | 展示 | 展示 |
| 动作反馈 | 通用模板 | 结合身体数据增强 |
| 练习时长/命中数/连续打卡 | 可按实现情况展示 | 必须展示 |
| 食谱 | 锁图标与蒙层 | 单条推荐卡片 |
| 操作 | 完成打卡 / 再练一次 / 分享琴谱 | 同左 |

### 分数

```text
分数 = ceil(命中式数 / 8 × 100)
```

| 命中数 | 评价 |
|---|---|
| 8 | 行云流水，古琴已为你而鸣 |
| 6–7 | 渐入佳境，再练几遍会更稳 |
| 3–5 | 动作初成，坚持自有回响 |
| 小于 3 | 八段锦在于坚持，明天继续 |

### 反馈模板

- 动作纠错：第 {{n}} 式“{{式名}}”时，{{问题描述}}；
- 改正方法：下一次练习时，{{具体建议}}；
- 明日目标：{{目标内容}}；
- 鼓励话语：{{鼓励语}}。

普通版展示固定模板与单次识别数据；定制版根据身体数据做适度替换，避免生成医疗判断。

## 5.9 音疗页

### 定位

音疗页是自由播放器，不识别动作、不计入跟练动作判定。音乐来自独立的赏听/点单轨，不与跟练阶段音乐库混用。

### 页面内容

- 标题：弦养 · 点单；
- 引导：今天想照顾哪里？；
- 选择：心 / 肝 / 脾 / 肺 / 肾；
- 快捷按钮：说不上来，随便听听；练完了，听一首完整的；
- 当前音色、曲目列表、播放/停止；
- 低频切换的呼吸字幕：慢吸 / 慢呼 / 放松。

界面展示“想照顾哪里”和氛围标签，不将五音五脏关系写成医疗建议。

## 6. 推荐系统与内容逻辑

## 6.1 推荐输入

### 快速问卷输入

- 不适部位；
- 久坐时长；
- 运动基础；
- 当日氛围；
- 可投入时长；
- 拳种偏好；
- 膝盖不适。

### 定制输入

- 身体基础数据；
- 运动损伤/慢性疾病自述；
- 目标；
- 饮食偏好；
- 食谱接收偏好。

## 6.2 基础推荐规则

| 条件 | 推荐 |
|---|---|
| 颈肩/腰背不适 + 久坐 | 八段锦 + 商调或宫调 |
| 睡眠/情绪问题 | 八段锦 + 羽调或角调 |
| 零基础 + 时间紧 | 八段锦招牌 3 式 |
| 膝盖不适 | 避开马步/深蹲倾向动作，优先安全提示 |
| 帮我选 | 八段锦 + 宫调 + 平和承载 |

规则采用“条件命中 + 默认值”的确定性方案，Demo 阶段不引入复杂模型。

## 6.3 五行五脏编排原则

产品采用五行作为文化编排锚点，而不是绝对音高锚点：

- 二式：商 / 肺；
- 三式：宫 / 脾；
- 五式：徵 / 心；
- 六式：羽 / 肾；
- 七式：角 / 肝；
- 一、四、八式：起势 / 中段 / 收势骨架。

这套关系只用于解释层、氛围层和文案层，不改变 P0 的“第几式对应第几弦”技术契约。

### 音层与势层解耦

| 层 | 职责 |
|---|---|
| 音层 | 整段一个五音基调，负责氛围 |
| 弦层 | 一至七弦反馈，负责动作命中即时声音 |
| 势层 | 八式自身的升、降、开、合，负责动作体验 |
| 解释层 | 文案、点单和路演讲述，可使用五行意象 |

因此，任意八式都可以在任意五音基调下练习，不能把产品表述成八式与五音的严格一一对应。

## 6.4 阶段音乐库

| 阶段 | 形态 | 用户感知 | 实现要求 |
|---|---|---|---|
| 一·学架子 | 点 | 一个动作一声，用户慢它等用户 | 无节拍、氛围音固定开启，电平约 0.055 |
| 二·找气感 | 线 | 五声短句连成一条线 | 可循环、命中触发一句、留呼吸，氛围音降至约 0.033 |
| 三·入静 | 面 | 连续音乐，不感知单个音 | 约 12 分钟连续弧线，音乐掌拍，不叠加额外氛围音 |

跟练轨使用自产合成音，赏听轨使用授权清晰的真人演奏录音，两者不可相互替代。

## 7. 技术架构

### 7.1 总体架构

```text
手机浏览器
  ├─ Vue 页面与路由
  ├─ 摄像头 MediaStream
  ├─ MediaPipe Pose Lite + 本地 WASM/模型
  ├─ 姿态判定器
  ├─ onHit(stringIndex) 事件
  ├─ 古琴单音/和声播放
  ├─ localStorage 本地记录
  └─ fallback.mp4 预录兜底

本地静态服务
  └─ Node 内置 http server / HTTPS 辅助方案
```

### 7.2 技术选型

| 层 | 选型 |
|---|---|
| 前端工程 | Vite + Vue 3 + vue-router |
| 姿态识别 | `@mediapipe/tasks-vision` Pose Landmarker Lite |
| 模型资源 | 本地 `pose_landmarker_lite.task` |
| WASM | 本地 vision WASM，禁止运行时依赖 CDN |
| 判定 | 关节角、关键点关系、保持帧、每式锁存 |

| 存储 | localStorage，所有读写 try/catch |
| 服务 | Node 内置 http server；移动端摄像头使用 HTTPS |
| 兜底 | 本地 `fallback.mp4` |
| 样式 | CSS Design Tokens + 系统字体 |

### 7.3 资源与离线要求

必须随构建产物提供：

## 14. 路演讲解脚本

### 14.1 30 秒版本

> 弦养是一款不用安装的手机网页。用户对着摄像头练八段锦，系统用姿态识别判断动作；每做对一个动作，就拨响一根古琴弦。八式完成时七弦齐鸣，练习就像弹完一曲古琴。它不需要登录和后端，模型、声音和记录都能在本地运行，断网也能演示。

### 14.2 现场演示顺序

1. 打开首页，强调唯一主按钮“开始练”；
2. 点击并允许摄像头；
3. 退后约 2 米，展示全身和骨架；
4. 做“双手托天”，等待弦响；
5. 展示七弦进度；
6. 如条件允许完成八式，展示七弦齐鸣与总结；
7. 回到首页，展示本地打卡记录；
8. 需要时拔网线，展示离线能力；
9. 摄像头异常时演示预录兜底，不让现场停住。

### 14.3 不要这样讲

- 不要说“治疗”“治愈”“祛湿”“根治”；
- 不要说五音五脏存在绝对医学对应；
- 不要把五禽戏说成已经支持识别；
- 不要把 44 首曲目说成已经全部拥有合法音源；
- 不要把预录兜底说成实时识别。

## 17. 可执行实现补充

本节为补齐开发文档提出的**建议实施规格**。除已注明的来源契约外，字段、路由、阈值与指标需要产品和技术负责人确认后落地，不应称为已实现。

### 17.1 建议路由与模块划分

| 路由 | 页面 | 建议模块 |
|---|---|---|
| `/loading` | 启动加载 | 资源准备、首次进入判断 |
| `/welcome` | 欢迎 | 本地 onboarding 状态 |
| `/questionnaire` | 快速问卷 | 答案校验、推荐规则 |
| `/` | 首页 | 推荐卡片、入口、当日状态 |
| `/prepare` | 跟练准备 | 模式、音乐阶段、取景说明 |
| `/train` | 实时跟练 | 摄像头、骨架、判定、音频、状态机 |
| `/summary/:id` | 总结 | 按 sessionId 查询记录，不依赖易丢失的内存参数 |
| `/sound` | 音疗 | 曲库、授权、播放器、呼吸字幕 |
| `/me` | 我的 | 身体数据与阶段信息 |
| `/profile` | 身体数据 | 同意、录入、编辑、删除 |
| `/record` | 历史记录 | 复用现有路径，完整版历史可延后 |
| `/guide` | 动作指南 | 复用现有路径，定格照与文字 |

建议使用 hash 路由兼容静态交付；技术实现可调整路由命名，但用户流程不能变。识别引擎、音乐引擎、推荐规则、存储服务与 UI 分离，防止页面直接修改判定器内部状态。

### 17.2 练习状态机

```text
IDLE → PREPARING → CAMERA_REQUESTING → MODEL_LOADING → CALIBRATING
                                                       ↓
                                                TRAINING / PAUSED
                                                       ↓
                                         COMPLETED 或 EARLY_ENDED
                                                       ↓
                                                   SUMMARIZED

权限拒绝 / 资源失败 / 持续无信号 → FALLBACK（明确示例模式）
恢复摄像头 → 重新校准 → 用户确认恢复识别
```

- 每次仅一个推理循环；上次推理未结束，不堆积下一帧；
- 页面后台、暂停、授权拒绝和低可信度时不继续累计动作保持时间；
- 退出页时停止 MediaStream tracks、推理计时器、语音队列和音频；
- 切换摄像头先停止旧流，新流未就绪时不丢当前会话；
- 刷新后恢复设置，但回第 1 式，不自动把半次练习标记完成；
- 完成、提前结束、预录、手动等来源都必须具有不同结果标签；
- 第 8 式仅在真实时序判定通过时计真实命中；切换兜底不得伪造姿态成功。

### 17.3 动作识别开发任务

| 式 | 需要观测 | 校准与反例 |
|---|---|---|
| 1 双手托天 | 双腕相对头肩高度、双肘展开、稳定保持 | 举一只手、挥手不能命中 |
| 2 左右开弓 | 一侧伸展、另一侧屈肘、手臂方向 | 双臂自然平举不等于开弓 |
| 3 单举 | 一腕举高、另一腕下按、左右可镜像 | 与托天区分，不因镜像漏判 |
| 4 往后瞧 | 头部转向与肩部/躯干稳定关系 | 转身不是转头；不把二维估计当临床角度 |
| 5 摇头摆尾 | 躯干俯身加左右时序摆动 | 单次弯腰或关键点丢失不能计完成 |
| 6 攀足 | 髋/躯干俯身与双手靠近腿足区域 | 与第五式区分，手乱摆不能命中 |
| 7 攒拳 | 腿部稳定、手臂推出关系与时序 | 单靠 Pose 不可声称精确识别握拳或怒目 |
| 8 七颠 | 脚跟起落、身体高度变化、连续周期 | 排除镜头晃动、随意跳动；目标 7 次，次数与安全降级需确认 |

最终角度、可见度、幅度、持续时间应写入带版本的数据文件；在定格照、真实正例、原地晃动反例上调参，不在文档中虚构“已验证最佳阈值”。首选时间保持而非固定帧数，低帧率时仍按真实持续时间判定。招牌三式使用原始式号 1、2、7，分别触发弦 1、2、7，不重排为 1、2、3。

### 17.4 推荐确定性与冲突优先级

建议计算顺序：

1. 安全约束先于强度偏好：存在膝盖不适或受伤自述，不推荐深蹲挑战；
2. 用户明确拳种偏好先记录，但仅有八段锦可练时显示能力提示；
3. 用户明确氛围优先于系统自动氛围；
4. 用户选择“帮我选”时根据状态取基础规则；
5. 零基础且仅 5 分钟优先招牌模式；
6. 无规则命中回到八段锦、宫调默认。

商调/宫调、羽调/角调的二选一尚未完全冻结。建议首版固定颈肩久坐→商、睡眠放松→羽、情绪且提振→角、平和→宫；“提振→徵”等补充映射须负责人批准后写入版本化规则，不随机选调。10 分钟偏好不等同已有 10 分钟课程，首版提示仅有约 5/12 分钟两种模式。

安全约束如无法生成已验证的替代动作，应进入“降低幅度、遵循个人能力/咨询专业人员”提醒或仅音频体验，不能擅自生成医疗康复方案。急性疼痛、眩晕等出现时立即停止，不为了触发声音鼓励用户加大幅度。

### 17.5 数据契约补全

建议记录以下对象，使用统一 `schemaVersion` 并提供迁移和失败降级：

| 对象 | 关键字段 | 约束 |
|---|---|---|
| Onboarding | welcomed、questionnaireStatus | 区分未答、已答、跳过；欢迎不重复 |
| Preferences | answers、selectedForm、tone | 不储存医疗诊断，拳种选择与实际课程分开 |
| BodyProfile | heightCm、weightKg、age、limitations、goals、diet、recipeOptIn、consentedAt | 类型/范围校验，数据不全不自动进入定制 |
| Session | id、mode、moveIds、musicStage、tone、startedAt、durationSec、status、source | `source` 为 camera/video/manual/mixed；计时剔除暂停 |
| MoveResult | moveId、recognized、reasonCode、qualityAvailable、hitAt | 不识别不等于动作做错；无证据不生成纠错 |
| Record | sessionId、dateKey、hitCount、score、checkInConfirmed | 保存幂等，重复点击完成不重复累计 |
| Settings | audioEnabled、volume、voiceEnabled、voiceRate、cameraDeviceId、aspectRatio、resolution | 设备 ID 失效回默认，不白屏 |
| Track | id、title、file、durationSec、license、sourceUrl、attribution、toneConfidence | 无本地音源不可播放，授权待核不公开发布 |

建议内部事件使用 `sessionId + moveId` 去重；适配器将命中事件转换为既有 `onHit(1..7|'choir')`，保持冻结播放契约不变。

“累计练习次数”和“连续打卡天数”分开：一天多练可增加会话次数，但同日仅一个打卡日期；连续天数按设备本地自然日计算，跨时区/修改系统时间的边界需说明。等级判断先算高级，再中级，最后初级，避免满足高级却显示中级。

### 17.6 评分、琴谱与反馈口径

全套固定分母 8；招牌模式分母 3 为待确认建议。必须同时展示“识别命中 N/M 式”，不能把模式相异的分数当作同一动作质量评价。

- 100 分只能代表目标式数全部命中，不代表动作完美或健康水平；
- 琴谱可视化使用弦触发次数/顺序/时刻，不将起伏伪称真实身体数据；
- 未命中：显示“本式未检测到完成，尝试让关键部位入镜”，而非编造具体错误；
- 只有具有可信错误特征时，才展示该特征对应改正建议；
- 七颠未完成或用户提前结束时不得强制“七弦齐鸣”；
- 原定“今日琴谱”标题在普通版是否保留、普通版是否展示详细练习统计，需产品确认；建议统一保留基础统计以便验收；
- 食谱理由仅介绍普通饮食与偏好，禁止宣称某食物治疗肩颈/疾病；过敏信息未采集前不生成个性医疗食谱。

### 17.7 本地隐私与删除

- 摄像头画面和姿态关键点只用于当前设备处理，默认不上传、不保存视频；
- 申请摄像头前说明用途，不申请麦克风；
- 身体数据录入前单独告知目的、保存位置、删除方式与非医疗用途；
- 默认本地存储，不宣传其为加密保险箱；同设备共享浏览器可能看到记录；
- 删除身体数据时清理 BodyProfile、衍生推荐缓存和食谱偏好，恢复普通版；是否同时清空历史需另行明确选择；
- 提供“清空全部本地数据”的确认，不将数据清空与日常返回绑定；
- 日志不输出完整身体数据、视频截图或证书私钥；
- 默认不接云分析、不引入账号；后续云同步属于独立版本，须重新设计同意与权限体系。

## 18. 非功能要求与离线发布策略

### 18.1 离线分层

| 情形 | 能力定义 | 验收方式 |
|---|---|---|
| A 电脑无互联网 | Node 本地服务与本地资源可用 | 断开外网后访问 localhost 完整练习 |
| B 手机无外网但局域网仍在 | 手机仍能访问同 Wi-Fi 的 HTTPS 服务 | 关闭广域网，不断 Wi-Fi，走全流程 |
| C 手机飞行模式且网络全断 | 首次已缓存后，重新打开仍可用 | Service Worker 缓存页面/模型/WASM/音频/兜底后，开飞行模式冷启动验收 |

A/B 不能替代 C。未做持久离线缓存时，页面内已加载资源短时继续运行，不等于离线冷启动。P0 中飞行模式硬要求若保留，则须开发 C 并显示“离线资源准备完成”；首次无网络且从未缓存不能承诺可用。

建议使用版本化缓存清单、资源完整性检查和旧缓存回收；模型/WASM 优先预缓存，非必要语音大文件按需加载。手机存储配额失败时明确提示，不强行宣称离线已就绪。

### 18.2 HTTPS 与静态服务

- 电脑本地 `http://localhost:5173` 可用于本机调试；
- 手机需要受设备信任的 HTTPS。自签证书仅测试使用，不把团队根证书视为面向公众的默认方案；
- 证书需匹配访问地址，私钥不能进入公开静态目录；
- 补充 MP3/OGG/WAV 等正确 MIME；验证媒体 Range 请求以支持视频拖动与音频加载；
- 静态文件路径校验使用路径边界校验，避免简单前缀比较造成同名前缀目录绕过；
- HTML 默认及时更新，哈希资源可采用长缓存；离线缓存与构建版本一致；
- 不根据部署辅助页存在就判定 HTTPS、手机摄像头或远程访问已成功。

### 18.3 性能与兼容建议

| 项 | 开发建议 / 指标性质 |
|---|---|
| 摄像头 | 默认 640×480，1280×720 可选；不支持时回退 |
| 推理 | 初始目标 15 FPS 左右，设备低于能力时自适应；需真机实测 |
| 命中声音 | 在保持判定通过后尽快播放，建议 p95 延迟 ≤200ms，不包含 300–500ms 保持时间 |
| 视频兜底 | 故障被确认后到首帧 ≤3 秒；另记录“发生故障→检测故障”耗时，不混淆 |
| 加载 | 展示授权、模型、摄像头、校准四步；有超时和取消，不无限加载 |
| 可访问性 | 44px 点击区、充足对比度、音频静音、状态不只依赖颜色 |
| 测试矩阵 | iOS Safari、Android Chrome、目标手机实际浏览器、电脑 Chrome/Edge；具体 OS/版本留验收实填 |

以上性能数字除来源已有保持时间/兜底指标外，是建议验收目标，未做本次实测。内嵌浏览器若能力受限，提供“在系统浏览器打开”提示，不保证所有内嵌环境可授权。

## 附录 B. 最终结论

弦养的交付主线不是增加页面数量，而是把“动作识别→弦音反馈→练习总结→本地坚持记录”做成可信闭环。完整产品在此基础上接入五音氛围、点线面阶段音乐、自由赏听和可删除的定制数据；所有扩展都必须守住**本地优先、播放契约明确、真实识别与演示分离、文化叙事不医疗化**四条边界。
