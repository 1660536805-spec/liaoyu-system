作品简介

居家运动与传统功法跟练，只告诉用户练了多久，却答不出做对了什么：动作缺即时反馈，练习单调难坚持。弦养以手机摄像头为输入，构建端侧多模态算法系统：基于 MediaPipe Pose 提取 33 点骨架，自研「关键点净化—尺度归一化—几何打分—时序互斥仲裁」四段式八段锦动作判定算法，经事件契约 onHit(1..7|choir) 把判定映射为古琴七弦与七弦齐鸣，辅以五音三阶段音乐调度与本地优先推理。动作达标即拨响琴弦，单帧判定 O(1)，保持帧与锁存使原地晃动 10 秒零误触发，断网可跑，练完一套即成一曲。零安装零登录，可用于居家康养、社区养老、文旅等场景，并可通过同一契约接入音箱、香薰等硬件。

一、项目概述

（一）项目背景与意义

1. 痛点：跟练产品的「反馈断点」

现有的居家健身与八段锦、太极等传统功法跟练产品，绝大多数只能记录时长与热量，很少回答用户最关心的那个问题——「我这一下，做对了吗？」具体表现为三点：

  • 反馈缺失：动作是否达标缺乏即时、可感知的回应，用户只能「凭感觉」；
  • 完成感弱：练习过程单调重复，缺少一个「我今天完成了什么」的收束；
  • 闭环断裂：不少摄像头应用停留在「看见人」（骨架可视化），识别结果没有转化成用户能感知的反馈。

其结果是：用户知道要坚持，却不知道每一次坚持换来了什么，动力自然衰减。公式化地说，问题出在链路的一个断点上：

做动作  →  反馈弱  →  不知道是否做对  →  动力弱  →  难以坚持
                ▲
            本作品要补上的「反馈断点」

2. 机会：让姿态识别的结果「听得见」

八段锦有八式、古琴有七弦，二者天然同构：前七式一式一弦，第八式收势七弦齐鸣。这让「一次正确的动作 = 一声古琴」成为可能——把抽象的识别分数，直接转译成即时、可记忆的听觉反馈，形成闭环：

动作命中  →  弦位亮起  →  古琴出声  →  用户记住「我做到了」

由此，练习不再需要用户去「读懂」技术：做完一套八段锦，就等于弹完一曲古琴。东方美学与身心疗愈的调性，也恰好契合「OPC 时代身心疗愈」的命题方向。

3. 技术意义

  • 面向真实输入的鲁棒判定：手机摄像头画面存在抖动、遮挡、出画、镜像等低质量问题，需要专门的关键点净化、阈值标定与防误触算法；
  • 端侧本地优先：姿态模型、推理 WASM、音频与练习记录全部本地运行，断网可跑、零后端、零依赖，天然适合弱网、离线与私有化场景；
  • 可插拔的接口契约：用统一事件契约把「识别」与「播放」解耦，使系统能低成本接入更多输入/输出设备。

（二）赛题方向定位

本作品参加AI 算法创新赛 · AI+软件赛道，交付形态为一个可现场演示的端到端系统原型（手机浏览器 H5，打开网址即可运行），而非 PPT 方案或接口草案。

在命题层面，弦养对应企业命题三「OPC 时代身心疗愈」，选择的方向是「五音疗愈音频能力 × AI 动作识别能力」的组合；在算法与工程层面，作品的重点落在四件事上：

二、技术方案与核心算法

（一）系统总体方案与架构

1. 端到端数据流

系统的主链路是「一帧画面 → 一次判定 → 一声琴音」，全程在浏览器端完成：

手机摄像头画面 (MediaStream)
   ↓
MediaPipe Pose Landmarker Lite  ← 本地 WASM + 本地模型（不依赖 CDN）
   ↓
33 点人体关键点 (归一化坐标) + 33 点 3D 世界坐标 (米制，原点在髋中心)
   ↓
关键点净化器 createLandmarkCleaner   ← 越界剔除 / 低置信剔除 / 坐标冻结
   ↓
尺度归一化 & 几何特征构造            ← 以「肩宽 T」为尺度的相对量
   ↓
八式判定器 MoveJudge                 ← 打分 → 时序特征 → 互斥仲裁 → 保持帧 → 每式锁存
   ↓
onHit(stringIndex)   1..7 = 第 1~7 弦 ；'choir' = 第七弦齐鸣
   ↓
古琴音合成 + UI 状态更新 + 本地练习记录（localStorage）

主链路之外还有两个旁路模块：陪练教练状态机负责调度「示范 / 跟练 / 完成」的节奏；取景伺服逐帧计算「上半身可见度 / 下半身可见度 / 取景完整度」三个真实指标，用于引导用户后退取景，并驱动半身模式的降级逻辑。

3. 四层解耦架构与 onHit 可插拔契约

为了让「文化」不被写死进代码、「设备」可以随时替换，系统在工程上分成互相隔离的四层，只通过稳定契约通信：

层职责数字化落点
音层整段一个五音基调，负责氛围音频基调参数（五调式）
弦层一至七弦，动作命中的即时声音onHit(1..7)
势层八式自身的升、降、开、合八式动作判定器
解释层文案 / 点单 / 路演中的五音五脏意象内容数据

对外最小切面 —— 音频契约

onHit(stringIndex)　// stringIndex ∈ { 1,2,3,4,5,6,7 } ∪ { 'choir' }

识别侧只负责产出 onHit 事件；音频侧只消费 onHit，不关心动作信号从哪来（真实识别 / 预录兜底 / 手动触发可互换）。任何新的输入源（体感手柄、可穿戴 IMU）或输出源（音箱、香薰机、灯带）只需实现同一契约即可接入，核心链路一行不改——这就是「可插拔」的工程含义。

因此，八段锦任意一式都能在任意五音基调下练习，文化层与工程层互不绑架。

（二）核心算法设计

本章是报告的重点，按数据流的处理顺序，逐层说明系统中的核心算法：从关键点净化，到几何特征构造，再到八式判定、时序仲裁、稳健性设计、教练状态机，最后是音频调度。

1. 人体姿态估计与关键点净化算法

① 姿态估计的工程配置

姿态估计采用 VIDEO 模式、单人体（numPoses=1）。三个内部置信度阈值（检测 / 存在 / 跟踪）均设为 0.4，低于模型默认值——原因是真机实测中，远处或暗光时关键点可见度普遍偏低（右手腕一度只有 0.47），沿用默认阈值会把真实动作整式拦掉。引擎在 GPU delegate 初始化失败时会自动退回 CPU，并对部分驱动挂起做超时兜底；模型只加载一次，切换摄像头不重载。

② 关键点净化算法（三道处理）

实测 8797 帧数据证明：关键点抖动与可见度强相关（右腕在可见度 > 0.85 时抖动 0.069，可见度 < 0.3 时抖动 0.202，相差约 3 倍）；且 MediaPipe 对「画面外 / 遮挡」的点并非返回空值，而是给出一个数学连续、物理无意义的猜测坐标（例如脚踝 y 跑到 1.55，即画面外 55%）。这类坐标会严重污染「手到脚距离」等几何量，因此必须净化。净化器 createLandmarkCleaner 对 12 个躯干/四肢关键点做三道处理：

序处理规则与动机
①越界剔除x / y 超出 [−0.005, 1.005]（略放宽，MediaPipe 边缘点会轻微越界）即判无效
②低置信剔除visibility < 0.30 即判无效（实测该阈值以下抖动为可信帧的 3 倍）
③坐标冻结无效点的坐标沿用上一帧有效值，避免几何量突变；整帧无任何有效点时返回 null，让上层跳过本帧判定

设计取舍：为什么「净化而不滤波」？

我们刻意不做时序平滑。消融实验表明：中值 5 + EMA 0.5 可使抖动下降 42%，但真实动作的速度分量仅保留 52%，判定会明显迟钝、动作跟不上。于是选择「剔除坏点 + 冻结坐标」的净化策略，把「是否可信」交给下游的可见度门槛去判断——宁可不判，不误判。

③ 头部朝向的解算

第 4 式「五劳七伤往后瞧」需要判断头部转向。仅用「鼻 + 双眼」三点存在两个问题：正侧面转 90° 时鼻子投影不再明显；且无法区分「头在转」与「整个人在转」。因此系统取用 MediaPipe Pose 的全部头部关键点（鼻、双眼内/外眼角、双耳、双嘴角共 11 点）并结合 3D 世界坐标：

  • 耳间距的投影变化 → 侧面程度（头转 90° 时两耳前后重叠，投影最小）；
  • 鼻相对双耳中点的偏移 → 头部朝向；
  • 眼/口连线与双耳连线的夹角 → 头部 yaw（左右转角）。

当 3D 数据不可用时，相关式子直接判 0，避免用不可靠的 2D 投影硬判。

2. 尺度归一化与几何特征构造

用户离摄像头有远有近，绝对像素坐标无法直接比较。系统统一以肩宽作为尺度基准：

T = max(ε, ‖ L_shoulder − R_shoulder ‖)　（ε = 1e-3，防止除零）

所有几何特征都表示为「多少倍肩宽」，从而使判定与离摄像头远近无关。三个归一化打分核定义了「特征如何折算成 0~1 的分数」：

打分核定义语义
ok(x, lo, hi)1 − clamp₀¹((x−lo)/(hi−lo))x 越小越好（lo 得 1，hi 得 0）
okUp(x, lo, hi)clamp₀¹((x−lo)/(hi−lo))x 越大越好（lo 得 0，hi 得 1）
okDown(x, good, bad)1 − clamp₀¹((x−good)/(bad−good))x 越小越好（good 得 1，bad 得 0），独立实现以免区间倒序踩坑

在此之上构造的核心几何量包括：手腕相对肩线的上升量 raiseL / raiseR、躯干前倾角 leanDeg = atan2(|Δx|, |Δy|)、三点夹角 angle(a,b,c)、手到同侧脚踝距离 handToAnkle、双脚间距 feetSpread，以及肩中点 / 髋中点 shoMid / hipMid。

3. 八式动作判定算法

八式各对应一个纯函数打分器 fᵢ(p) : Landmarks → [0,1]，输出为若干归一化特征的加权和。判定遵循「硬门槛先行、加权打分为主」的原则：不满足硬门槛（如「手举过头顶」「躯干站直」）直接判 0，不进入加权，从而在源头上掐掉误判。下面以三个代表式说明其判定逻辑（完整特征与权重见附录表）。

① 第 1 式「双手托天理三焦」——静态姿态型

核心是「双臂高举过顶」。区间按真人比例标定（单位 = 肩宽 T）：手举过头顶时手腕约在肩线上方 1.8~2.2T，双腕分开约 1.5~2.0T，肘接近伸直。四个特征加权：

lower_raise = min(raiseL, raiseR)          较低那只手腕也要高过头   okUp(·,1.0,1.9)  权重 0.28
avg_raise   = (raiseL + raiseR)/2          平均举高                 okUp(·,1.2,2.2)  权重 0.26
elbow_str   = (∠左肘 + ∠右肘)/360°         双肘接近伸直             okUp(·,0.78,0.94) 权重 0.24
apart       = ‖双腕距离‖/T                 双腕分开程度             okUp(·,1.3,2.4)  权重 0.22
score₁ = 0.28·lower_raise + 0.26·avg_raise + 0.24·elbow_str + 0.22·apart

② 第 5 式「摇头摆尾去心火」与第 6 式「两手攀足固肾腰」——时序型 + 互斥设计

这两式都是俯身动作，单帧几乎无法区分，因此引入滑动窗口时序特征与互斥硬门槛：

  • 第 5 式主信号是双手横摆幅度 __handSwing（摇头摆尾时手随身体左右摆动，腕中点持续横移），要求 __handSwing ≥ 0.18 T，否则判 0；
  • 第 6 式（攀足）是双手定点下探、几乎不横摆，要求 __handSwing ≤ 0.26 T，否则判 0；
  • 二者共同要求时序窗口已就绪（__ready），否则判 0——防止「静止的攀足」被误判成「摆动的摇头摆尾」。

此外，第 5 式还实测发现：摇头摆尾时两肩基本同向平移，肩线倾斜量仅约 0.04 肩宽、恒不达标，故改用「躯干整体左右横移 __sway」而非「肩线一高一低」作为辅助信号。

③ 第 7 式「攒拳怒目增气力」——镜像自适应

原先的实现硬编码「左手在画面左侧」，即假设 fwdL < 0。但实测 8797 帧中发现 95.6% 的帧呈现「左肩 x > 右肩」（画面被水平镜像）。硬编码会导致第 7 式在镜像下判定失效。现改为从双肩实际位置推断「出拳方向」：

leftOnScreen = (L_shoulder.x < R_shoulder.x)    // 左肩是否在画面左侧
outward      = leftOnScreen ? −1 : +1           // 出拳方向
scoreL = fwdL · outward ;  scoreR = fwdR · outward
出拳手 = 「更向外伸」的那只（score > 0.2），与镜像 / 朝向无关

同时用 atWaist（另一手须收在腰侧，兼作硬门槛）把「左右开弓」挡在外面，避免第 2 式被第 7 式压过。

4. 时序特征与互斥仲裁机制

① 滑动窗口时序特征

系统维护一个长度为 45 帧（约 1.5s @30fps）的滑动窗口，窗口内不足 12 帧时视为「时序信号未就绪」，相关式子一律判 0。窗口上计算四个时序特征：

特征含义用途
__bob躯干中点的垂直起伏幅度 / T第 8 式「踮脚」的主信号
__sway躯干中点的横向摆幅 / T第 5 式辅助
__handSwing双腕中点的横摆幅度 / T第 5 式主信号、第 6 式互斥门槛
__handGap双腕间距的变化量第 5 式辅助

起伏源自适应：髋部关键点可见时用髋中点，不可见时自动退回肩中点（肩的可见度常年约 0.99，最稳）。

② 保持帧 + 每式锁存 + 互斥仲裁

判定状态机 MoveJudge 在每帧执行以下步骤：

① 打分：对 8 个规则函数求值，得 sc[0..7]
② 选最优：best = argmax(sc)
③ 仲裁：要求 sc[best] ≥ THRESHOLD(0.55)  且  lead = sc[best] − second ≥ MARGIN(0.10)
④ 保持：命中则 counts[best]++ ，否则清零
⑤ 锁存：当 counts[best] ≥ holdFrames(12，约 0.4s) 且该式未锁存 → 触发一次，并置 latched[best]=true（同式不再重复响）

其中「保持帧」过滤掉骨架的瞬时抖动，「每式锁存」保证同一式不会连续狂响。此外系统提供顺序模式（八段锦是顺序练的，即产品主用模式）：只判定当前指定式、不做仲裁，可彻底消除式间串扰；自由模式才启用「领先幅度 MARGIN」仲裁。当某式要求头部转到指定角度时，头未到位则整式判 0。

5. 稳健性设计：抗误触发与降级

真实场景中摄像头可能只拍到上半身（近距离取景），此时下肢关键点不可靠。为此系统设计了三层稳健性机制：

机制规则
可见度门槛任一依赖点的 visibility 低于门槛即该式记 0 分（VIS_MIN = 0.35；实测 0.5 会误拦真实动作，0.35 仍足以挡住真正出画的点）
半身模式髋降级近距离取景时髋贴边、可见度落到 0.15~0.35 之间。髋在躯干上、人体先验强，坐标仍可信，故只把髋门槛降到 0.15（HIP_VIS_HALF）；而膝/踝是肢体末端，出画后返回的是 y>1 的猜测坐标，门槛一律不放宽（LEG_VIS = 0.35）
下肢降级路径当膝盖/脚踝不可用时，第 5 / 6 / 8 式自动切换到「纯上半身信号」分支（如第 8 式改用「双手垂于体侧 + 躯干规律起伏」当踮脚信号），保证仍可判定

这一设计直接支撑了验收项 D7（抗误触）与半身取景场景下的可用性。

6. 陪练教练状态机

仅有判定器时，用户并不知道下一步该做什么，标准骨架在原地无限循环；而且一旦判定不命中，就会永远停在同一式。为此设计了陪练教练状态机 coach.js——一个纯函数（只暴露 tick(dtMs)，不读系统时钟、不开定时器），因此可以在 Node 里跑单元测试，也能在页面不可见时暂停计时。

begin(idx)
   │
   ▼
 demo ── 教练示范（动一遍后停在结束姿态）
   │ demoDone() / demoMaxMs 保底
   ▼
 follow ── 用户跟练：判定器武装，等做到位
   │   ├─ hit(idx) ────────────→ done（完成）
   │   └─ 判定闸门下每 attemptMs → nudge（重播示范 + 轮次+1，仍留在 follow）
   ▼
 grace ── 宽限期：仍可命中；extend() 可延长
   │   └─ hit / extend → follow ；graceMs 到 → advance(timeout)
   ▼
 done ── 极短庆祝（doneMs 后）→ advance(done) → 进入下一式

状态机支持两档「闸门」，决定「什么时候进入下一式」：

闸门行为用途
judge（默认）判定闸门：只有判定命中才进下一式；没通关就永远停在这一式，每 attemptMs 重播一遍示范（轮次 +1）。它不是「停死」——画面一直在动、轮次可见、调用方保留「跳过本式」手动出口「一个动作没通关就一直练这个动作」
time计时闸门：到点自动放行，即使一直没做到位也会在硬上界内进入下一式先过一遍流程；也用于做 A/B 反证测试

两档节奏预设（race = 完整 / 精简）：

参数fullshort含义
attemptMs1500010000判定闸门下重播示范的间隔
demoMaxMs90005000示范阶段保底时长（防卡在 demo）
doneMs900700「很好！」停留时长
graceMs80006000宽限期时长（仅 time 档）

① 五音定弦：可播放的频率表

弦音名频率 (Hz)弦音名频率 (Hz)

三弦角220.89七弦商（高）392.88

② 点 / 线 / 面三阶段音乐调度

阶段形态用户感知
一 · 学架子点一个动作一声，用户慢它就等
二 · 找气感线五声短句连成一条线
三 · 入静面约 12 分钟连续音乐弧线

③ 12 分钟弧线调度算法

「面」阶段由弧线引擎 arc.js 实现，是系统中最「音乐」的一段算法：

  • 同构结构：总长 720 秒，划分为 9 段（起势 → 收功）；五个调式共用同一条九段结构，只换「动机落音」和「低音主音」；
  • 同宫系统：音高集合恒为 F G A C D（简谱 1 2 3 5 6）五个音，调式只决定「谁当家」；每种调式自带 7 条动机（A/B/E/D/C/C2/P/Z）；
  • 前瞻调度：以 TICK_MS = 130ms 为排程检查间隔，LOOK = 2.0s 为前瞻窗口，提前把进入点落在窗口内的音符排入播放队列；
  • 强度曲线：段内强度随进度线性变化 i(sec, u) = i₀ + (i₁−i₀)·u，配合每段的密度、音区、明暗、力度等参数形成一张「情绪波形」；
  • 七弦齐鸣：弧线中固定存在两个齐鸣时刻 CHOIRS = [630, 712] 秒，与调式无关（属弦层事件）。

这一层把「文化编排」变成了可计算、可调度的数据结构，同时严格通过 onHit 与识别层解耦。

序创新点说明

4. 算法复杂度分析

判定链路全部为轻量级几何运算，满足手机端实时性要求：

环节时间复杂度说明
关键点净化O(K)，K=12固定 12 个点，常数级
八式打分O(N)，N=8每式固定数量特征，与人数/画面无关
时序特征更新O(W)，W=45滑动窗口仅入队/出队；极值用窗口内常数扫描
仲裁与锁存O(N)一次求最值与次最值
单帧合计O(1)与画面分辨率、人体数量、练习时长均无关

内存方面，判定器仅维护 4 个长度为 45 的窗口数组与若干计数器，占用为常数级；模型推理开销由 MediaPipe 承担（本地 WASM，约 5.5MB 模型）。

        ↓

4. 可插拔生态与硬件扩展

在事件总线之后挂一层适配器，即可向外延伸（以下接口位已预留、尚未实现）：

  • 输出侧：智能音箱 / 古琴音箱（音频）、智能香薰控制 API（香方 → 扩香节奏）、氛围灯、中控屏；
  • 输入侧：体感手柄、可穿戴 IMU 等，只需实现 onHit 契约；

因本地优先、零后端，弦养尤其适合弱网、离线与私有化部署的场景。我们给出的是一套可插拔的架构与契约，而不是「已经对接了香薰机」的既成事实。
