## 四、新建 `verify-current.cjs`：设计要点

**为什么另起一支**：历史脚本每个轮次都要新基线，且 POST 与别人的 PRE 撞车。本脚本改为**自更新基线**——`--update` 存当前渲染，之后要求逐字符复现。

**① 归一化随时间漂移的字段**（否则过一天/跨一个节气就假阳）。首页有三处由「当天日期 / 节气」算出：

```
<div class="jq">今日 · <span class="o">寒露</span></div>   ← 节气名
<div class="date">10月11日 农历九月初二</div>              ← 公历 + 农历
<p class="desc">露气寒冷，将凝为霜，…</p>                  ← 节气养生文案
```

比对前替换为 `__JQ__ / __DATE__ / __DESC__`；**当前真实取值仍打印**，不会被藏起来。
> 只对 `home` 生效——其余屏（如 `body` 的 `.desc` 是静态文案）**原样参与逐字符比对**，不做旁路。

**② 双档**：

| 档 | 视口 | 为什么 |
|---|---|---|
| `mobile` | 470×900 @dsf2 | 主壳设计基准（9 稿 941×1672 的等比档） |
| `desktop` | 1280×900 | `7be5159` 新增的桌面层（≥960px 惰性注入侧栏 + 分列），**没有基线钉住就等于没人看** |

**③ 捕获根用 `body`**（不再用 `.phone`）：桌面层的 `.dt-side` 是注入到 `body` 的，用 `.phone` 会漏掉整个侧栏。
桌面档须**等桌面层就绪**（`html.dt` 已置位且 `.dt-side` 在场）再抓，否则抓到的是未分列的原生单列。

**④ 自检「服务的 app.js ≡ 仓库 dist/app.js」**（sha256）：预览服务有缓存/旧构建残留时，验的就不是线上那份 —— 这道自检把「验收本身失效」也拦下来。

**⑤ 断言清单**

| 组 | 内容 |
|---|---|
| 自检 | 服务端 `/app.js` sha256 ≡ 仓库 `dist/app.js` |
| 桌面档结构 | `html.dt` 置位 + `.dt-side` 在场；侧栏 **6** 项（底部 5 项 + 桌面专属 `go-body`＝身体数据）；侧栏前 5 项 data-a 顺序 ≡ 底部导航；底部导航已隐藏；`home` 已分列（`main > .dt-col` ×2）；横向无溢出 |
| 证据一 | 双档 × 10 屏，归一化后**逐字符相同** |
| 证据二 | 导航 5 项、顺序＝首页/音疗/开始练/问询/我的、第 3 项＝开始练（居中不变） |
| 证据三 | 问询往返：点导航→高亮切换、种子 2 条、发送→4 气泡、输入框清空、占位标注、快捷问句填入、回车可发 |
