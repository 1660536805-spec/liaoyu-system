# 第四步 · 底部导航栏固定为 4 项 —— 验证记录

> 用户口径：**「测试发现没练前导航栏 3 个，练完导航栏 4 个，现在固定导航栏为 4 个」**
> 结论：**已修复并验收通过**。现在凡是有底部导航的屏，一律 4 项（首页 / 音疗 / 开始练 / 我的）。

---

## 1. 先复现：到底哪些屏是 3 项、哪些是 4 项

实测（`outputs/branch-merge-review/probe-nav.cjs`，470×900 真机渲染）：

| 屏 | 项数 | 文案（· = 高亮） |
|---|---|---|
| audio（音疗） | **4** | 首页  **·音疗**  开始练  我的 |
| home（首页） | **3** | 音疗  开始练  我的 ← **缺「首页」** |
| profile（我的） | **3** | 音疗  开始练  **·我的** ← **缺「首页」** |
| loading / question / intro / practice / done / body | 0 | （这些屏**本就没有**底部导航） |

⇒ 用户看到的「3 → 4」＝ **首页/我的页 3 项** vs **音疗页 4 项**。

## 2. 根因（一行）

`dist/app.js` 的底部导航由 `nav(cur, four)` 渲染，**「首页」那一项被 `four` 参数闸住**：

```js
function nav(cur,four){var h='<nav class="nav">'
 if(four)h+='<button class="nitem'+(cur==='home'?' on':'')+'" data-a="nav-home">'+ic('home')+'首页</button>'   // ← 只有 four 为真才画
 h+='...音疗...' +'...开始练...' +'...我的...'
```

而 3 个调用点里**只有音疗页传了 `four=true`**：
- `pgAudio`  → `nav('audio',true)` → 4 项
- `pgHome`   → `nav('home')` → 3 项（而且 cur='home' 匹配不到任何项 ⇒ **首页页连高亮都没有**，是同一个 bug 的另一面）
- `pgProfile`→ `nav('profile')` → 3 项

## 3. 修复（最小改动）

去掉 `four` 闸门，**「首页」永远渲染**：

```diff
-function nav(cur,four){var h='<nav class="nav">'
- if(four)h+='<button class="nitem'+(cur==='home'?' on':'')+'" data-a="nav-home">'+ic('home')+'首页</button>'
+function nav(cur){var h='<nav class="nav">'
+ h+='<button class="nitem'+(cur==='home'?' on':'')+'" data-a="nav-home">'+ic('home')+'首页</button>'
```

只动 2 行；`nav('audio',true)` 的多余实参在 JS 里被忽略，无需改调用点。
