四条红线（违反会直接扣分甚至取消资格）

① 绝不编造数据——没有测到的指标就写「未测」，宁可分数低也不能造假；② 绝不诱导受访者——不暗示"应该觉得好"，开放题先听后记；③ 绝不承诺疗效——弦养是运动与音乐体验产品，访谈中不得说"能治病、能改善颈椎"这类话；④ 绝不露出学校信息——本册衍生的所有图表、引语、录像，在对外提交前必须确认已移除学校名称、校徽与指导教师姓名，这是赛规明确写出的公平性要求。

场景定位（三场景兼顾，但只有一条主线）

赛题规则要求"选取某一细分场景"，并列三个会削弱创新性得分。因此本册按一条主线 + 一层延展设计：

主场景（P0）：养老场景的「机构日间带练 → 居家自练延续」双场地闭环——同一批老人、同一套系统、两个场地，练完回家能接着练。落地证明只需一个社区活动室。

延展场景（P1）：校园 / 职场久坐人群。同一技术底座的复制能力，只用于证明「推广路径」，不占主线篇幅。

一、调研设计说明

1.1 为什么 5 个人也够？——方法论辩护

这是评委最可能质疑的一点，必须答得出来。三条依据：

  • 可用性问题发现率曲线（Nielsen 1993）：单个用户能发现约 31% 的可用性问题，5 个用户累计可发现约 85%。5 人是「发现可用性问题」的公认拐点，再多边际收益骤降。本项目要的是发现问题，不是做统计推断。
  • 单被试内配对设计，抵消个体差异：我们不做「弦养组 vs 对照组」的两组比较（5 人做两组没有统计力），而是让同一个人在同一场次里先后做「静音跟练」和「弦养跟练」，比较配对差值。个体差异被自身抵消，5 对配对数据即可看到稳定的方向性差异。
  • 顺序效应已做抵消：一半被试按 A→B 顺序，另一半按 B→A 反序。若两种顺序下的差值方向一致，说明差异来自条件本身而非练习疲劳或新奇感。

诚实边界：5 人样本只能支持「小规模可用性测试 + 方向性证据」，不能外推为人群统计结论。方案中将如实标注样本量与方法，不做过度声称。

1.5 不能做的事

  • 不要为了凑数拉人：宁可 3 人真实，不要 5 人造假；
  • 不要在受访者面前评价产品，不要说"这个特别好用对吧"；
  • 不要替受访者操作。他卡住时先等 15 秒，再问"你现在在想什么"，最后才给最小提示，并在记录表标注需要协助；
  • 不要把技术侧自测数据混进用户数据（如 8797 帧标定属于算法验证，不是用户体验）；
  • 不要录制受访者面部后对外传播。录像只用于内部复盘。

六、访谈提纲

半结构化：按顺序问，但允许追问。每类 8 题，控制在 6 分钟内。括号内是追问方向，不必逐字念。

6.1 老年用户（S1 / S2）— 主场景 · 居家自练

  1. 您现在平时会做哪些活动身体的事？（每天/每周几次？在哪儿做？一个人还是有伴？）
  2. 有没有跟着手机或电视上的视频练过？练了多久就停了？为什么停？（追问具体的一天，不要接受"忙"这种笼统答案）
  3. 练的时候，您怎么知道自己做对了没有？（有谁纠正过您吗？）
  4. 如果做了一个动作却不知道对不对，您心里是什么感觉？（追问情绪词：着急？无所谓？）
  5. 您觉得"练了多久"和"练对了几个动作"，哪个对您更重要？为什么？
  6. 假如手机能在您做对的那一下响一声——您觉得会怎么样？会不会吵？（不要引导，让受访者自己说）
  7. 家里网络怎么样？会不会担心要装软件、要注册？（追问：谁帮您装？你自己会吗？）
  8. 如果要用摄像头对着您，您心里会有什么想法？

收尾必问（金句来源）：这件事您最希望它替您解决掉的是什么？用一句话说说。

6.2 社区/养老机构工作人员（S3）— 主场景 · 机构带练

  1. 咱们这里平时怎么组织长辈们活动？（频次、时长、谁带、多少人一次？）
  2. 带大家一起练八段锦或类似活动时，最难的是什么？（追问：人手不够？没人会带？长辈参与度低？）
  3. 活动室的设备和网络情况怎么样？（有没有电视/投影？WiFi 稳不稳？）
  4. 如果有一套系统，打开大屏就能带着一屋子人练，还有人能听出来自己练对了——您觉得能用上吗？
  5. 您最担心的是什么？（追问：学不会？设备坏？没人维护？老人抗拒摄像头？）
  6. 如果要给长辈们推荐一个每天花十分钟做的事，您会推荐什么？为什么？

8.3 跑完数据后怎么出图

打开终端，cd 到台账所在的文件夹，执行（脚本与本册、台账放在同一目录）：

python 弦养_调研统计出图.py  "弦养_试点数据台账.xlsx"  charts

仓库内的工作副本路径为 outputs/aic-scene/stats.py，与本册交付的 弦养_调研统计出图.py 是同一份文件。

脚本会输出到 charts/ 目录：① 指标.json（全部关键指标）；② 结论.md（可直接粘进方案的 Markdown 结论文字，数字全部来自台账，缺数据会明确提示"未测"，不会自动补数）；③ 五张图表 PNG（痛点强度、SUS 分布、配对差值、任务完成率、NPS 构成）。

脚本只依赖 openpyxl 与 Pillow，不依赖 matplotlib / pandas，也不需要联网；未填数据时不会崩，会直接把该指标标为「未测」。

8.4 如果最终只招到 3 个人

照跑，不要凑数。方案中如实写"小规模可用性测试，N=3"，并把 7.5 的三项技术侧自测补上。评委会因为"方法诚实、结论与样本量匹配"给出中档分，这比虚报 30 人最后被追问要好得多。
